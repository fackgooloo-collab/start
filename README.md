# 찌릿찌릿 포트폴리오

외주 문의를 위한 반응형 포트폴리오와 관리자용 프로젝트 CRUD입니다. 브랜드 소개, 서비스, 작업 사례, 진행 과정, 문의 영역을 갖추고 있습니다. 브랜드 문구는 한 파일에서 바꿀 수 있고, 작업 사례는 SQLite에 저장되므로 다른 웹사이트의 기반으로 재사용할 수 있습니다.

[포트폴리오 화면](docs/preview.png) · [관리자 화면](docs/admin-preview.png)

## 개발 환경

Node.js **24 이상**이 필요합니다. 저장소의 `.node-version`을 사용하세요.

```bash
npm ci
npm run dev
```

브라우저에서 `http://localhost:5173`을 엽니다. Vite는 5173, API는 3001 포트에서 실행되며 `/api` 요청은 개발 프록시로 전달됩니다. 종료는 `Ctrl+C`입니다.

클라우드 작업마다 기존 체크아웃에서 개발하면 됩니다. 별도 Git worktree 생성은 필요하지 않습니다.

## 관리자와 프로젝트 관리

`/admin`에서 로그인한 뒤 프로젝트를 추가·조회·수정·삭제할 수 있습니다. 비공개 프로젝트는 관리자에게만 보이며, 공개로 전환하면 포트폴리오에 반영됩니다. 추천 설정으로 대표 프로젝트를 지정할 수 있습니다. 삭제한 데이터는 자동 복구되지 않습니다.

최초 로컬 개발에서는 `localhost` 또는 `127.0.0.1`로 접속해 `/admin`에서 비밀번호를 정할 수 있습니다. 외부 주소로 접속하는 클라우드 미리보기 및 운영 환경에서는 다음 명령으로 먼저 비밀번호를 설정하세요.

```bash
npm run admin:setup
```

입력은 터미널에서 숨겨지며, 비밀번호는 12~128자입니다. 다시 실행하면 비밀번호를 바꾸고 기존 로그인 세션을 만료합니다. 비밀번호는 salt를 적용한 scrypt 해시로 저장됩니다. 운영 환경의 웹 화면에서는 최초 관리자 설정을 허용하지 않습니다.

`ADMIN_PASSWORD` 환경변수가 있으면 저장된 비밀번호보다 우선합니다. 플랫폼의 비밀 환경변수 설정에 입력하거나, Git에 포함되지 않는 `.env`를 사용하세요. 비밀번호를 소스 코드, 셸 명령 인자 또는 Git에 기록하지 마세요. 환경변수를 사용한 로그인 세션은 서버가 재시작되면 만료됩니다.

## 브랜드 및 콘텐츠 변경

- `src/site.ts`: 상호, 문구, 서비스, 진행 과정, 이메일 및 SNS 주소를 변경합니다.
- `index.html`: 다른 브랜드로 재사용할 때 검색·공유에 쓰이는 페이지 제목과 소개 메타데이터도 변경합니다.
- `/admin`: 작업 제목, 분류, 연도, 설명, 고객, 태그, 표지, 외부 링크, 추천 및 공개 여부를 변경합니다.
- 기본 작업 4건은 **가상 브랜드로 만든 구성 예시**이며 실제 납품 실적이 아닙니다. 실제 작업으로 교체하거나 삭제하세요. 모두 삭제해도 서버가 예시를 다시 생성하지 않습니다.
- 연락처는 기본값이 비어 있습니다. 실제 문의 이메일 또는 SNS 주소를 `src/site.ts`에 넣어 문의를 연결하세요. 현재 문의 영역은 별도 문의 접수·메일 발송 시스템을 제공하지 않습니다.

표지는 네 가지 기본 이미지(`coffee`, `beauty`, `architecture`, `finance`) 또는 외부 HTTPS 이미지 주소를 사용할 수 있습니다. 외부 이미지는 해당 주소의 제공 상태에 영향을 받습니다. 작업 링크는 HTTP/HTTPS 주소만 허용합니다.

입력 제한은 제목 100자, 짧은 소개 160자, 설명 3,000자, 고객 100자, 태그 최대 8개(각 32자), 주소 2,000자입니다. 연도는 네 자리 숫자입니다.

## 빌드와 운영

```bash
npm run build
npm run admin:setup
npm start
```

운영 서버는 `dist`의 정적 웹 화면과 API를 함께 제공합니다. 기본 주소는 `http://127.0.0.1:3001`입니다. 실제 서비스는 HTTPS 리버스 프록시를 사용하고 원래 요청의 `Host`를 유지하세요. 관리자 쿠키는 운영 환경에서 `Secure`로 발급됩니다.

`.env.example`을 참고해 필요한 설정만 `.env` 또는 플랫폼 환경변수에 추가합니다. 실행 스크립트가 `.env`를 읽습니다.

| 변수 | 기본값 | 용도 |
| --- | --- | --- |
| `HOST` | `127.0.0.1` | API가 바인딩할 주소. 컨테이너 외부 접근이 필요한 배포에서는 `0.0.0.0` |
| `PORT` | `3001` | API 및 운영 웹 서버 포트 |
| `DATABASE_PATH` | `.data/portfolio.sqlite` | 영구 저장할 SQLite 파일 경로 |
| `ADMIN_PASSWORD` | 없음 | 선택적인 관리자 비밀번호. 저장된 비밀번호보다 우선 |
| `PUBLIC_ORIGIN` | 요청의 프로토콜과 Host | HTTPS 프록시 뒤에서 실제 외부 주소, 예: `https://portfolio.example.com` |

`PUBLIC_ORIGIN`에는 경로나 마지막 `/`를 넣지 않습니다. 변경 요청은 브라우저의 `Origin`과 사이트 주소가 일치해야 합니다. API에 비밀 환경변수를 전달하는 프런트엔드 코드는 없습니다.

SQLite 파일이 유지되는 서버 또는 컨테이너에서 실행하세요. 여러 서버가 동일 파일을 공유하는 구성, 읽기 전용 파일 시스템, 매 요청 파일이 사라지는 서버리스 환경에는 맞지 않습니다. 배포 시 `.data` 또는 `DATABASE_PATH`의 디렉터리를 영구 볼륨으로 연결해야 작업과 관리자 설정이 유지됩니다.

백업할 때는 먼저 서버를 정상 종료하고 `.data` 디렉터리 전체를 복사합니다. 운영 중에는 SQLite 백업 기능을 제공하는 도구를 사용하세요. 실행 중인 SQLite 본 파일만 복사하면 WAL에 있는 최근 데이터가 빠질 수 있습니다. 복구는 서버를 종료한 상태에서 백업 디렉터리를 되돌린 뒤 시작합니다. DB와 `.env`는 개인정보 및 인증 정보를 포함할 수 있으므로 접근을 제한하세요.

## 검증

```bash
npm test
npm run build
```

API 테스트는 별도의 임시 SQLite 파일을 사용하며 실제 `.data`를 건드리지 않습니다. 최초 설정, 로그인·로그아웃, 권한, 전체 CRUD, 비공개 작업 접근, URL 및 입력 검증, 재시작 후 유지, 예시 재생성 방지, 세션 만료, 로그인 시도 제한을 확인합니다.

브라우저 테스트는 Playwright로 실행할 수 있습니다.

```bash
npx playwright install chromium
npm run test:e2e
```

브라우저 테스트도 별도의 임시 DB와 5174/3002 포트를 사용합니다. 공개 필터·상세 보기·모바일 메뉴·오류 후 재시도, 최초 관리자 설정·입력 검증·전체 CRUD·공개 전환·로그아웃·재로그인을 실제 브라우저에서 확인합니다. 시스템 Chromium이 있으면 사용하고, 다른 실행 파일은 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`로 지정할 수 있습니다.

## API

읽기 응답은 `{ projects: [...] }` 또는 `{ project: {...} }`, 오류는 `{ error: "설명" }`입니다. 변경 요청에는 JSON 본문과 같은 사이트의 `Origin`이 필요합니다. 관리자 인증은 HTTP-only 쿠키를 사용하며 브라우저 저장소에 토큰을 저장하지 않습니다.

| 경로 | 동작 |
| --- | --- |
| `GET /api/health` | 서버 상태 |
| `GET /api/projects` | 공개 프로젝트 목록 |
| `GET /api/projects/:id` | 공개 프로젝트, 로그인한 관리자는 비공개도 조회 |
| `GET /api/admin/projects` | 관리자용 전체 목록 |
| `POST /api/projects` | 관리자 프로젝트 생성 |
| `PATCH /api/projects/:id` | 관리자 프로젝트 수정 |
| `DELETE /api/projects/:id` | 관리자 프로젝트 삭제, 성공 시 204 |
| `GET /api/auth/status` | 로그인 및 최초 설정 가능 여부 |
| `POST /api/auth/setup` | 로컬 개발의 최초 비밀번호 설정 |
| `POST /api/auth/login` | 관리자 로그인 |
| `POST /api/auth/logout` | 관리자 로그아웃 |
